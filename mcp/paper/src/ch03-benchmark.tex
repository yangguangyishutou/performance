\subsection{Dataset Schema}


Each data entry in the dataset is organized in JSONL format and consists of five core fields: the id field serving as a unique identifier; the score field defining the weighting; the metadata field storing the name, language type, and textual description of the vulnerability; the assets field storing the core source code content through a nested structure; and the ground\_truth field providing the judgment baseline.


\begin{itemize}
    \item \textbf{Id}: The unique index for the data.
    \item \textbf{Score}: Used to set the sample score. This paper assigns 2 points for correctly identifying a vulnerability sample and 1 point for correctly identifying a secure sample. This differentiated scoring strategy simulates real-world auditing logic: the systemic risk caused by missing a critical vulnerability (false negative) is far higher than that of misreporting a safe fragment (false positive). Therefore, this field ensures that the evaluation score authentically reflects the actual auditing capability of the model under test.
    \item \textbf{Metadata}: Providing background information on the sample, including the programming language and a textual description of the vulnerability.
    \item \textbf{Ground truth}: Serves as the objective criterion for evaluation. In addition to a boolean vulnerability judgment, it contains detailed risk classifications and corresponding CWE IDs. This structured labeling system allows the benchmark to determine not only whether the model answers "correctly" but also, through more complex parsing processes, whether it locates the vulnerability "accurately."
    \item \textbf{Assets}: The core of this benchmark. This field stores the complete source code files in a nested array format. Structurally, the assets data constructed in this paper perfectly aligns with real-world MCP interaction scenarios.
\end{itemize}

\subsection{Metrics}



% 1.	基础分类指标（准确率、精确率、召回率）：
% 准确率（Accuracy）衡量模型整体判断的正确比例性。精确率（Precision）侧重于评估模型报警的质量，即在模型判定的漏洞中，真实漏洞所占的比例，用于衡量虚警风险。召回率（Recall）则反映了模型发现潜在漏洞的能力，即在所有真实漏洞中，被成功检出的比例。这三个指标构成了评估模型基础审计能力的基石。
% 2.	同答比 (PCR)： 同答比是衡量模型是否具备真实安全逻辑理解力的核心指标。其计算逻辑是：将数据集按照逻辑关联进行配对（每一对包含一个漏洞样本及其对应的安全样本），只有当模型能够同时准确识别出该组内的漏洞与安全性时，才判定该组“同答正确”。 
% 该指标的作用在于剔除那些依靠关键词匹配或猜测而获得的偶然正确得分，强制模型证明其能够区分微小的防御逻辑差异。


\textbf{Precision and Recall.} Accuracy measures the proportional correctness of the model's overall judgments. Precision focuses on evaluating the quality of the model's alerts, i.e., the proportion of real vulnerabilities among the vulnerabilities identified by the model, used to measure false alarm risk. Recall reflects the model's ability to discover potential vulnerabilities, i.e., the proportion of successfully detected vulnerabilities among all real vulnerabilities. These three metrics constitute the cornerstone for evaluating the model's basic auditing capability.


\textbf{Pairwise Correct Ratio.} The traditional Accuracy metric has limitations when evaluating the code security of large models because it cannot distinguish whether the model truly understands the code logic or merely relies on shallow feature matching of specific API keywords (e.g., os.system). Additionally, a single metric easily masks the model's tendency toward over-refusal.
To this end, we introduced the Pairwise Correct Ratio (PCR) as a core consistency metric. Its calculation logic is as follows: the dataset is paired according to logical correlation (each pair contains a vulnerability sample and its corresponding secure sample). A pair is judged as "pairwise correct" only when the model can accurately identify both the vulnerability and the security within that group simultaneously. This metric effectively eliminates accidental correct scores obtained through keyword matching or guessing, forcing the model to prove its ability to distinguish subtle differences in defense logic.

\begin{equation}
    PCR = \frac{N_{both_correct}}{N_{total_pairs}} 
\end{equation}
