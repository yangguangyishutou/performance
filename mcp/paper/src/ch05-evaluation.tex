\subsection{Experiment Setup}

% 2.5.1 实验过程的随机化与抗欺骗设计

\textbf{Evaluated Baselines.} We evaluate a diverse set of baselines, ranging from state-of-the-art LLMs to industry-standard security analysis platforms, including \textbf{GPT-5-mini}~\cite{gpt5mini}, \textbf{Claude Haiku 4.5}~\cite{claude}, \textbf{DeepSeek-V3.2}~\cite{DeepSeekAI2025DeepSeekV32PT} , \textbf{AI-Infra-Guard}~\cite{aiinfraguard} (Released by Tencent Zhuque Lab in 2025) and \textbf{Bandit}~\cite{badit} (Originally developed by the OpenStack Security Team).

\textbf{Configuration.} We set the generation temperature to 0.0, disable streaming, and use a 120-second timeout per API request. The evaluation employs dual prompts: a system prompt defining the five MCP vulnerability types, and a user prompt containing the raw Python code of the target server. Security tools (Bandit and AI-Infra-Guard) are run with default settings. To prevent models from exploiting sample order, we shuffle the JSONL dataset with \texttt{random.shuffle()} and a fixed seed, ensuring each sample is evaluated independently.


% \textbf{Random Input Samples.} 

% A model's output is often influenced by the context order or the position of samples in the dataset. To prevent the tested model from ``cheating'' by recognizing patterns in the sample sequence, the evaluation program fully shuffles the sample order after loading the JSONL dataset using the \texttt{random.shuffle()} API driven by a random seed. This testing order ensures that the model processes each sample in an independent decision-making environment, eliminating position bias from affecting the experimental results. 


\textbf{Prompt Design.} We use a zero-shot, role-playing prompting strategy for LLM evaluation, separating the prompt into a system and a user prompt to ensure clarity and output stability. The system prompt assigns the role of an “expert security researcher” for Python MCP auditing and embeds the full vulnerability taxonomy, including code-level indicators across five categories. Responses are strictly constrained to a JSON schema with \texttt{is\_vulnerable}, \texttt{vulnerability\_type}, and \texttt{reasoning} fields. The user prompt provides only the raw Python source code.
