# 基于动态算子的层次化代码分词器与压缩机制

在本项目中，我们旨在从信息论角度出发，通过挖掘代码自身的结构特性来进行 Token 的无损高密度压缩。为了克服 TokenSugar 和 SimPy 中“静态硬编码规则”的局限性，我们设计了一套**完全动态、自适应的层次化算子挖掘与压缩架构**。

以下是该系统的核心机制梳理：

---

## 1. 挖掘形式 (Mining Mechanism)

挖掘的核心由 `frequency_miner.py` 驱动。它放弃了传统 BPE 仅看“相邻字符/Token频率”的盲目匹配，而是通过**结构化抽象**（AST 与词法分析）来寻找代码库中真正高频的“骨架”。

挖掘主要分为两个维度：

### 1.1 动态语法骨架挖掘 (Syntax Operator Mining)
系统会使用 Python 的 `ast` 模块遍历所有训练集代码，并动态提取代码的骨架。
* **原理 (Anonymization)**：当遇到一个控制流或赋值语句时，提取器会将具体的变量名、常量名抠掉，替换为占位符 `{0}`, `{1}` 等。
* **示例**：
  * 遇到代码：`for index in range(len(items)):`
  * 抽象为骨架：`for {0} in range({1}):`
  * 遇到代码：`self.user_id = user_id`
  * 抽象为骨架：`self.{0} = {1}`
* **统计与注册**：系统会统计所有这些带孔位(Holes)的骨架的出现频率。最高频的骨架会被自动注册为一类特殊的**语法算子 Token**（例如：`<OP_AST_0>`）。

### 1.2 动态词法前缀挖掘 (Lexical Prefix Mining)
代码中的变量命名往往遵循特定的约定（如驼峰命名法、蛇形命名法），导致某些词根或前缀极度高频。
* **原理**：利用正则表达式分析标识符，提取高频的命名修饰符。
* **示例**：扫描到 `get_user`, `get_name`, `get_id`，系统会提取出公共前缀 `get_`。
* **注册**：这类高频前缀会被动态注册为**词法算子 Token**（例如：`<OP_PRE_0>`）。

> **总结**：所有的算子（Operators）都不是我们在代码里写死的，而是程序跑完您提供的数据集后，**根据该数据集特有的编码习惯，动态生成的**。

---

## 2. 压缩与编解码形式 (Compression & Tokenization)

拿到这些动态生成的算子后，`hierarchical_tokenizer.py` 接管了压缩的重任。它的本质是在原有的基础分词器（如 GPT-4 的 Tiktoken 或 CodeGen 的分词器）外层，包裹了一层**基于正则表达式的预编译器**。

### 2.1 编码压缩过程 (Encode)
当给定一段原始代码时：
1. **词法算子替换**：正则引擎扫描到 `get_apple`，由于我们之前注册了 `<OP_PRE_0> = "get_"`，它会被立刻替换为 `[<OP_PRE_0>, "apple"]`。
2. **语法算子替换**：正则引擎扫描到 `for i in range(n):`，匹配到了骨架 `for {0} in range({1}):`，它会被提取并替换为：`[<OP_AST_0>, "i", "\ue000", "n", "\ue001"]`。
   * *(注：`\ue000` 和 `\ue001` 是专用的不可见定界符，用于防止底层的 BPE 分词器把操作数意外粘连起来，保证结构清晰。)*
3. **底层 BPE 兜底**：替换完高频骨架后，剩下的普通代码文本（如变量名 `"apple"`, `"i"`, `"n"`）再交给底层的常规 BPE 分词器进行 Token 化。

**压缩收益**：原来一句 `for i in range(n):` 可能需要 6~7 个 Token，现在被压缩到了仅用 1 个算子 Token + 2 个变量 Token + 定界符，极大提升了信息密度。

### 2.2 无损还原过程 (Decode)
代码生成的最后一步必须能被 Python 解释器正确执行，因此我们要求 100% 的无损还原。
1. 将模型吐出的 Token IDs 交给底层 BPE 转回字符串（此时字符串里混杂着 `<OP_AST_0>` 等特殊算子）。
2. `HierarchicalTokenizer` 内部自动生成的反向正则表达式开始工作。
3. 遇到 `<OP_AST_0> i \ue000 n \ue001`，它会根据注册时的骨架 `for {0} in range({1}):`，把参数 `i` 填入 `{0}`，把 `n` 填入 `{1}`，完美重构出 `for i in range(n):`。

---

## 3. 大模型适配与语义保留 (Embedding Initialization)

因为这些 `<OP_AST_0>` 是刚刚动态生造出来的词，预训练好的大模型完全不认识它们。如果直接丢给模型，会导致严重的“语义空洞”（如同遇到噪声）。

为了契合我们**“信息论中建立语义层级联系”**的初衷，且尽量避免昂贵的全量训练，在 `embedding_init.py` 中我们使用了**均值池化 (Mean Pooling)** 的策略：

1. 提取算子的纯文本特征。对于 `for {0} in range({1}):`，我们剔除掉孔位，得到字符串 `for in range():`。
2. 用底层分词器对这句话分词，得到原本的一系列 Token IDs（比如 `[for], [ in], [ range], [():]`）。
3. 提取这些老 Token 在大模型底层矩阵中的 Embedding 向量，并**求取平均值**。
4. 将这个平均向量赋值给新的 `<OP_AST_0>` 作为初始权重。

**效果**：这样一来，即便是未经过任何微调的大模型，在第一次看到 `<OP_AST_0>` 时，其底层的向量计算也会立刻让模型产生“这大概跟循环遍历有关”的强烈先验直觉，从而实现了算子层面的语义继承！
