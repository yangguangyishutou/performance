\section{Empirical Evaluation}

This section presents a comprehensive evaluation of \tool{} on real-world Java projects. We assess the effectiveness of our hierarchical translation approach compared to baseline methods and analyze various aspects of translation quality.

\subsection{Research Questions}

Our evaluation addresses the following research questions:

\begin{itemize}
\item \textbf{RQ1}: How does the hierarchical translation approach affect compilation success rates compared to file-by-file translation?
\item \textbf{RQ2}: What is the impact of call graph-guided translation order on dependency correctness?
\item \textbf{RQ3}: How effective is the autonomous compilation agent in resolving translation errors?
\item \textbf{RQ4}: What types of translation errors are most common and how does our framework address them?
\end{itemize}

\subsection{Experimental Setup}

\subsubsection{Baseline Methods}
We compared \tool{} against two baseline approaches:

\begin{enumerate}
\item \textbf{Direct LLM Translation}: File-by-file translation using GPT-4 with minimal context
\item \textbf{Template-Based Translation}: Rule-based translation with predefined mapping patterns
\end{enumerate}

\subsubsection{Evaluation Metrics}
\begin{itemize}
\item \textbf{Compilation Success Rate}: Percentage of translated files that compile without errors
\item \textbf{Semantic Correctness}: Functional correctness measured through test cases
\item \textbf{Error Resolution Time}: Time taken by the compilation agent to fix errors
\item \textbf{Code Quality}: Cyclomatic complexity, maintainability index, and code similarity
\end{itemize}

\subsubsection{Implementation Details}
\begin{itemize}
\item LLM Models: DeepSeek-v3-250324 and GPT-4-turbo
\item Compilation Environment: clang++ with C++17 standard
\item Hardware: Intel i7-10700K, 32GB RAM, RTX 3080
\item Evaluation Runs: 5 runs per project with different random seeds
\end{itemize}

\subsection{Threats to Validity}

\textbf{Internal Validity}:
\begin{itemize}
\item Limited dataset size (4 projects) may not represent all Java patterns
\item Manual verification of semantic correctness may introduce bias
\item LLM model variations could affect reproducibility
\end{itemize}

\textbf{External Validity}:
\begin{itemize}
\item Focus on Java-to-C++ translation may not generalize to other language pairs
\item Selected projects primarily from library/utility domains
\item Evaluation limited to compilation success, not extensive runtime testing
\end{itemize}

\textbf{Construct Validity}:
\begin{itemize}
\item Compilation success rate may not fully capture translation quality
\item Semantic correctness assessment through limited test cases
\item Code quality metrics may not reflect real-world maintainability
\end{itemize}

\subsection{Discussion of Results}

The empirical evaluation demonstrates that \tool{} significantly improves Java-to-C++ translation quality through its hierarchical approach. Key insights include:

\begin{itemize}
\item The macro-to-micro translation strategy effectively reduces error propagation
\item Call graph analysis is crucial for maintaining dependency correctness
\item The autonomous compilation agent substantially increases final success rates
\item Memory management and generic type translation remain challenging areas
\end{itemize}

These results validate our hypothesis that project-level translation requires more sophisticated approaches than simple file-by-file processing, and that hierarchical translation with intelligent error recovery is a promising direction for automated code migration.
