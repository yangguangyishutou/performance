\section{Related work}


\paragraph{Traditional Neural Code Translation} Early neural code translation methods focused on sequence-to-sequence models and tree-based architectures. Chen et al.\cite{chen2018tree} first proposed a tree-to-tree model for code translation, Drissi et al. \cite{drissi2018program} improved the model by integrating target language syntax rules into the decoder,%, The model achieved 88.82\% average accuracy on FOR-to-LAMBDA synthetic tasks, 
but the reliance on parallel bilingual corpora and predefined grammar rules limited its generalization to real-world scenarios. Facebook AI's TransCoder \cite{roziere2020unsupervised} introduced unsupervised code translation using back-translation to learn language alignment without parallel corpora. However, Malyala et al. \cite{malyala2023ml} identified significant limitations in TransCoder's statistical nature, including syntax errors, semantic inconsistencies, and context confusion.
%% They proposed a hybrid approach combining rule-based preprocessing (e.g., loop conversion, type normalization) and postprocessing (e.g., removing spurious constraints) to improve translation accuracy by up to 86\% for Java-to-Python tasks.

\paragraph{LLM-Based Code Translation} With the rise of large language models (LLMs), researchers began exploring their potential for code translation. Sun et al.\cite{sun2022code} mentioned a method using large models to translate code into natural language. Yan et al\cite{yan2023codetransocean} systematicly tested the code translating performance of ChatGPT on their benchmark, Zhang et al. \cite{zhang2025function} proposed F2STRANS, a two-stage fine-tuning framework for code translation. Jiao et al. \cite{jiao2023evaluation} developed a taxonomy for evaluating neural code translation, classifying tasks into four difficulty levels.%: token-level (simple keyword mapping), syntax-level (structural transformation), library-level (API migration), and algorithm-level (logic rewriting). Their analysis showed that model performance degrades significantly with increasing task complexity, with BLEU scores dropping by up to 21.8\% from token-level to library-level tasks. 
Pan et al. \cite{pan2024lost} conducted a large-scale empirical analysis of LLM code translation errors, %identifying five major defect categories: language syntax/semantic mismatches (30.5\%), dependency/logic errors (24.2\%), data-related issues (33.5\%), model-specific artifacts (6.6\%), and other experimental problems (5.2\%).
the study found that even state-of-the-art models like GPT-4 achieved only 47.3\% correct translation rate on single-function tasks.



\paragraph{Project-Level Translation} Recent research has shifted to repository-level code translation to address real-world migration needs. Wang et al. \cite{wang2024repotransbench} introduced RepoTransBench, a benchmark with 1,897 real-world repository samples covering 13 language pairs. %Their evaluation revealed that even the best LLM-based approaches achieve only 32.8\% success rate on repository-level translation, with particularly low performance (below 10\%) for dynamic-to-static language migrations. 
Zhang et al. \cite{zhang2025skeleton} proposed a skeleton-guided translation framework that first extracts code structure and then fills in implementation details, but noted limitations in handling cross-language architectural differences. Zhou et al. \cite{zhou2025porting} developed ArkAdapter, a rule-based tool for migrating TypeScript/JavaScript libraries to OpenHarmony's ArkTS language.%, achieving 88.6\% success rate on 79 mainstream libraries through knowledge base-driven adaptation.

In summary, the introduction of large models has significantly raised the ceiling of code translation compared to traditional methods. Their ability to perceive long contexts and generalize has also opened up new possibilities for larger-scale translations, such as at the project level. However, research has also exposed a series of challenges faced by large models. For example, the increased project scale brings pressure on understanding and complex dependency relationships, as well as difficulties in interface mapping caused by different ecosystems and frameworks. Additionally, the widespread hallucination phenomenon in large models also causes considerable troubles since zero tolerance for errors is required in code generation.
