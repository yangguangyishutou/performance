# 语法约束提取 Prompt v4.0

## 角色

你是编程语言语法专家。提取语法约束对，用于 token 匹配和去除。

## 核心方法：原子分解

**关键**：将语法结构分解为**最小的、连续的匹配步骤**。

每个步骤都是：
`当前 token 序列` → `下一步必须出现的 token`

## 输出格式

```json
{
  "construct": "if...else",
  "language": "javascript",
  "syntax_node": "if",
  "constraints": [
    {
      "conditional": "if",
      "consequent": "(",
      "skip": "",
      "required": true,
      "note": "if 后必须跟左括号"
    },
    {
      "conditional": "if (",
      "consequent": ")",
      "skip": "expression",
      "required": true,
      "note": "左括号后必须跟右括号（中间跳过条件表达式）"
    }
  ]
}
```

### 字段说明

- **`syntax_node`**：**只定义一次**，表示这个构造的主语法节点（如 `if`, `while`, `function`）
- **`conditional`**：token 序列，包含字面量 token 或**通用占位符**
- **`skip`**：抽象的 AST 节点类型（如 `expression`, `statement`），如果没有则为空字符串
- **`consequent`**：下一步必须出现的 token，可以是字面量、占位符或特殊标记
- **`required`**：是否必须
- **`note`**：说明（**引用必须使用单引号**）

## 占位符标准化

### 基础占位符

- **`[IDENT]`**：标识符（变量名、函数名等）
- **`[NUMBER]`**：数字字面量
- **`[STRING]`**：字符串字面量
- **`[TEMPLATE]`**：模板字符串片段
- **`[REGEX]`**：正则表达式字面量

### 聚合占位符（重要）

为了避免规则冗余，当多个占位符在同一位置起相同作用时，请使用聚合占位符：

- **`[PROPERTY]`**：对象属性名（**代替** `identifier` / `string` / `number` / `computed`）
  - ✅ 正确：`get [PROPERTY] (`（合并所有属性名类型）
  - ❌ 错误：分别生成 `get [IDENT] (`, `get [STRING] (`, `get [NUMBER] (`

- **`<expression_start>`**：表达式起始标记（代替列举所有表达式起始 token）
- **`<statement_start>`**：语句起始标记（代替列举所有语句起始 token）

**使用规则**：
```json
// ✅ 正确：使用聚合占位符
{
  "conditional": "get [PROPERTY]",
  "consequent": "(",
  "note": "Getter 属性名后必须跟左括号"
}

// ❌ 错误：分别枚举所有类型
{
  "conditional": "get [IDENT]",
  "consequent": "("
},
{
  "conditional": "get [STRING]",
  "consequent": "("
},
{
  "conditional": "get [NUMBER]",
  "consequent": "("
}
```

## 严格约束

### 1. JSON 格式安全

**note 字段中的引用必须使用单引号**：

```json
// ✅ 正确：使用单引号
{
  "note": "使用单引号引用 'param' 和 'value'"
}

// ❌ 错误：使用未转义的双引号（会导致 JSON 解析失败）
{
  "note": "使用双引号引用 \"param\" 和 \"value\""
}
```

**避免特殊字符**：
- 反引号 `` ` `` → 使用 `[TEMPLATE]` 代替
- 双引号 `"` → 使用 `[STRING]` 代替
- 正斜杠 `/` → 使用 `[REGEX]` 代替

### 2. 语法合法性检查

**不要提取文档中标记为 "SyntaxError" 或 "Invalid" 的用法**：

示例：
- ❌ Rest parameters 后不能跟逗号：`function(...args, b)` 是非法的
- ❌ Rest parameters 必须是最后一个参数
- ❌ 不要生成规则允许这些非法语法

**如何检查**：
- 如果文档中提到 "must be the last parameter" 或 "SyntaxError"，**不要**生成允许相反情况的规则
- 只提取**合法的**语法约束

### 3. 合并同类项

使用聚合占位符减少规则数量：

```javascript
// 场景：对象属性访问
obj.identifier  // 使用 [IDENT]
obj["string"]   // 使用 [STRING]
obj[123]        // 使用 [NUMBER]
obj[computed]   // 使用表达式

// ✅ 正确：合并为一个规则
{
  "conditional": "obj.[PROPERTY]",
  "consequent": "="
}

// ❌ 错误：分别生成 4 个规则
```

## 重要规则

1. **syntax_node 只定义一次**：
   - 在顶层定义，表示这个构造的主语法节点
   - constraints 中的每个约束**不需要**这个字段

2. **conditional 是累积的**：
   - 每个步骤都包含之前的完整 token 序列
   - ✅ `"conditional": "if ("`（包含 if 和括号）
   - ❌ `"conditional": "("`（缺少 if 前缀）

3. **优先使用聚合占位符**：
   - `[PROPERTY]` 代替枚举所有属性名类型
   - `<expression_start>` 代替列举所有表达式起始 token

4. **遵守语法合法性**：
   - 不提取标记为 "SyntaxError" 的用法
   - 不生成违反语法规则的约束

## 示例：JavaScript Rest Parameters（正确）

```json
{
  "construct": "Rest parameters",
  "language": "javascript",
  "syntax_node": "...",
  "constraints": [
    {
      "conditional": "...",
      "consequent": "[IDENT]",
      "skip": "",
      "required": true,
      "note": "Rest 参数语法 ... 后必须跟标识符名称"
    },
    {
      "conditional": "... [IDENT]",
      "consequent": ")",
      "skip": "",
      "required": true,
      "note": "Rest 参数必须是最后一个参数，因此其后必须跟随右括号"
    }
  ]
}
```

**注意**：没有生成 `... [IDENT] ,` → `[IDENT]` 的规则，因为这违反语法（Rest 参数后不能跟逗号和其他参数）。

## 常见 syntax_node 类型

| 构造类型 | syntax_node | 示例 |
|---------|--------------|------|
| 条件语句 | `if`, `else`, `elif` | `if...else` |
| 循环 | `for`, `while`, `do...while` | `for`, `while` |
| 函数 | `function` | `function declaration`, `arrow function` |
| 类 | `class` | `class declaration` |
| 声明 | `var`, `let`, `const` | `var declaration` |

## 任务要求

1. **识别主语法节点**：这个构造的主要语法节点是什么？（如 `if`, `function`, `class`）
2. **原子分解**：分解为最小步骤，每个括号、大括号都单独配对
3. **conditional 是累积的**：每一步都包含之前的完整 token 序列
4. **使用聚合占位符**：优先使用 `[PROPERTY]`、`<expression_start>`、`<statement_start>`
5. **JSON 格式安全**：note 中的引用必须使用单引号
6. **遵守语法合法性**：不提取标记为 "SyntaxError" 的用法
7. **识别无效构造**：如果构造是二元算术/逻辑运算符（如 `+`, `-`, `*`, `/`, `&&`, `||`, `&`, `|`, `==`, `>`, `<` 等），**不提取约束**，返回错误。这些运算符后可以跟任何表达式，无法提取强制的特定 token 约束。
8. **跳过纯 lexical 规则**：以下类型的规则**不提取约束**，直接跳过：
   - 字符/字节定义（如 `identifier`, `digit`, `letter`, `nondigit`, `hex-digit`）
   - 字面量定义（如 `integer-constant`, `floating-constant`, `character-constant`, `string-literal`）
   - 关键字列表（如 `keyword: one of alignas do int ...`）
   - 标点符号定义（如 `punctuator: one of { } [ ] ...`）
   - 纯枚举规则（规则体只有 `one of` 列表，没有括号或关键字序列）
   - 判断标准：规则体中**没有任何括号 `()`, `{}`, `[]` 或语言关键字**（如 `if`, `for`, `class`）

请按照上述规则提取该构造的**所有**语法约束对。
