# 语法约束提取 Prompt v4.1

## 角色

你是编程语言语法专家。提取语法约束对，用于 token 匹配和去除。

## 核心方法：原子分解

**关键**：将语法结构分解为**最小的、连续的匹配步骤**。

每个步骤都是：
`当前 token 序列` → `下一步必须出现的 token`

## 输出格式

```json
{
  "construct": "if...else",
  "language": "javascript",
  "syntax_node": "if",
  "constraints": [
    {
      "conditional": "if",
      "consequent": "(",
      "skip": "",
      "required": true,
      "note": "if 后必须跟左括号"
    },
    {
      "conditional": "if (",
      "consequent": ")",
      "skip": "expression",
      "required": true,
      "note": "左括号后必须跟右括号（中间跳过条件表达式）"
    }
  ]
}
```

### 字段说明

- **`syntax_node`**：**只定义一次**，表示这个构造的主语法节点（如 `if`, `while`, `function`）
- **`conditional`**：token 序列，包含字面量 token 或**通用占位符**
- **`skip`**：抽象的 AST 节点类型（如 `expression`, `statement`），如果没有则为空字符串
- **`consequent`**：下一步必须出现的 token，**每个 consequent 只能包含一个值**
- **`required`**：是否必须
- **`note`**：说明（**引用必须使用单引号**）

## 占位符标准化

### 基础占位符

- **`[IDENT]`**：标识符（变量名、函数名等）
- **`[NUMBER]`**：数字字面量
- **`[STRING]`**：字符串字面量
- **`[TEMPLATE]`**：模板字符串片段
- **`[REGEX]`**：正则表达式字面量

### 聚合占位符（重要）

为了避免规则冗余，当多个占位符在同一位置起相同作用时，请使用聚合占位符：

- **`[PROPERTY]`**：对象属性名（**代替** `identifier` / `string` / `number` / `computed`）
  - ✅ 正确：`get [PROPERTY] (`（合并所有属性名类型）
  - ❌ 错误：分别生成 `get [IDENT] (`, `get [STRING] (`, `get [NUMBER] (`

- **`<expression_start>`**：表达式起始标记（代替列举所有表达式起始 token）
- **`<statement_start>`**：语句起始标记（代替列举所有语句起始 token）

**使用规则**：
```json
// ✅ 正确：使用聚合占位符
{
  "conditional": "get [PROPERTY]",
  "consequent": "(",
  "note": "Getter 属性名后必须跟左括号"
}

// ❌ 错误：分别枚举所有类型
{
  "conditional": "get [IDENT]",
  "consequent": "("
},
{
  "conditional": "get [STRING]",
  "consequent": "("
},
{
  "conditional": "get [NUMBER]",
  "consequent": "("
}
```

## consequent 拆分规则 (v4.1 新增)

**重要规则**：当语法允许一个位置有多个可能的 consequent 时，**必须为每个 consequent 生成独立的规则**。

### 错误示例 (❌ 不要这样做):
```json
{
  "conditional": "if ()",
  "consequent": "{, <statement_start>",  // 错误：逗号分隔多个值
  "note": "右括号后必须跟左大括号或语句起始"
}
```

### 正确示例 (✅ 应该这样做):
```json
[
  {
    "conditional": "if ()",
    "consequent": "{",  // 第一条独立规则
    "skip": "",
    "required": true,
    "note": "右括号后必须跟左大括号"
  },
  {
    "conditional": "if ()",
    "consequent": "<statement_start>",  // 第二条独立规则
    "skip": "",
    "required": true,
    "note": "右括号后必须跟语句起始"
  }
]
```

### 拆分规则总结：
1. **每个 consequent 字段只能包含一个值**
2. **多个选项必须拆分为多条独立的约束规则**
3. **每条规则具有相同的 conditional 但不同的 consequent**
4. **每条规则都应该有独立的 JSON 对象**

### 常见需要拆分的情况：
- `"{, <statement_start>"` → 拆分为 `{` 和 `<statement_start>`
- `"(, [IDENT]"` → 拆分为 `(` 和 `[IDENT]`
- `"=, {, <expression_start>"` → 拆分为 `=`, `{`, 和 `<expression_start>`

## 严格约束

### 1. JSON 格式安全

**note 字段中的引用必须使用单引号**：

```json
// ✅ 正确：使用单引号
{
  "note": "使用单引号引用 'param' 和 'value'"
}

// ❌ 错误：使用未转义的双引号（会导致 JSON 解析失败）
{
  "note": "使用双引号引用 \"param\" 和 \"value\""
}
```

**避免特殊字符**：
- 反引号 `` ` `` → 使用 `[TEMPLATE]` 代替
- 双引号 `"` → 使用 `[STRING]` 代替
- 正斜杠 `/` → 使用 `[REGEX]` 代替

### 2. 括号匹配验证 (v4.1 新增)

**生成 conditional 时必须确保括号正确配对**：

#### 括号配对规则：
- ✅ `"conditional": "if () {}"`  - 括号正确配对
- ❌ `"conditional": "if () }"`   - 错误（缺少左大括号）
- ❌ `"conditional": "if (}"`    - 错误（括号类型不匹配）
- ❌ `"conditional": "if ({})"`   - 错误（多余或错位）

#### 验证方法：
从左到右扫描 conditional 中的每个字符：
1. 遇到左括号 `(`、`[`、`{` 时压入栈
2. 遇到右括号 `)`、`]`、`}` 时检查是否与栈顶匹配
3. 确保所有左括号都有对应的右括号

#### 常见错误模式：
```
错误                    正确
---------------         -----------------
"if () }"        →      "if () {}"
"if ( {"         →      "if ({"
"function () }"  →      "function () {}"
"async () }"     →      "async () {}"
```

### 3. 语法合法性检查

**不要提取文档中标记为 "SyntaxError" 或 "Invalid" 的用法**：

示例：
- ❌ Rest parameters 后不能跟逗号：`function(...args, b)` 是非法的
- ❌ Rest parameters 必须是最后一个参数
- ❌ 不要生成规则允许这些非法语法

**如何检查**：
- 如果文档中提到 "must be the last parameter" 或 "SyntaxError"，**不要**生成允许相反情况的规则
- 只提取**合法的**语法约束

### 4. 合并同类项

使用聚合占位符减少规则数量：

```javascript
// 场景：对象属性访问
obj.identifier  // 使用 [IDENT]
obj["string"]   // 使用 [STRING]
obj[123]        // 使用 [NUMBER]
obj[computed]   // 使用表达式

// ✅ 正确：合并为一个规则
{
  "conditional": "obj.[PROPERTY]",
  "consequent": "="
}

// ❌ 错误：分别生成 4 个规则
```

## 重要规则

1. **syntax_node 只定义一次**：
   - 在顶层定义，表示这个构造的主语法节点
   - constraints 中的每个约束**不需要**这个字段

2. **conditional 是累积的**：
   - 每个步骤都包含之前的完整 token 序列
   - ✅ `"conditional": "if ("`（包含 if 和括号）
   - ❌ `"conditional": "("`（缺少 if 前缀）

3. **优先使用聚合占位符**：
   - `[PROPERTY]` 代替枚举所有属性名类型
   - `<expression_start>` 代替列举所有表达式起始 token

4. **每个 consequent 必须是单一值**：
   - ✅ `"consequent": "{"`
   - ❌ `"consequent": "{, <statement_start>"` （需要拆分为两条规则）

5. **遵守括号匹配规则**：
   - 确保 conditional 中的括号正确配对
   - 使用栈验证方法自检

## 示例：JavaScript Rest Parameters（正确）

```json
{
  "construct": "Rest parameters",
  "language": "javascript",
  "syntax_node": "...",
  "constraints": [
    {
      "conditional": "...",
      "consequent": "[IDENT]",
      "skip": "",
      "required": true,
      "note": "Rest 参数语法 ... 后必须跟标识符名称"
    },
    {
      "conditional": "... [IDENT]",
      "consequent": ")",
      "skip": "",
      "required": true,
      "note": "Rest 参数必须是最后一个参数，因此其后必须跟随右括号"
    }
  ]
}
```

**注意**：没有生成 `... [IDENT] ,` → `[IDENT]` 的规则，因为这违反语法（Rest 参数后不能跟逗号和其他参数）。

## 常见 syntax_node 类型

| 构造类型 | syntax_node | 示例 |
|---------|--------------|------|
| 条件语句 | `if`, `else`, `elif` | `if...else` |
| 循环 | `for`, `while`, `do...while` | `for`, `while` |
| 函数 | `function` | `function declaration`, `arrow function` |
| 类 | `class` | `class declaration` |
| 声明 | `var`, `let`, `const` | `var declaration` |

## 任务要求

1. **识别主语法节点**：这个构造的主要语法节点是什么？（如 `if`, `function`, `class`）
2. **原子分解**：分解为最小步骤，每个括号、大括号都单独配对
3. **conditional 是累积的**：每一步都包含之前的完整 token 序列

5. **consequent 拆分**：多个选项必须拆分为独立的规则，每个 consequent 只能包含一个值
6. **括号匹配验证**：确保 conditional 中的括号正确配对
7. **JSON 格式安全**：note 中的引用必须使用单引号
8. **遵守语法合法性**：不提取标记为 "SyntaxError" 的用法
9. **识别无效构造**：如果构造是二元算术/逻辑运算符（如 `+`, `-`, `*`, `/`, `&&`, `||`, `&`, `|`, `==`, `>`, `<` 等），**不提取约束**，返回错误。这些运算符后可以跟任何表达式，无法提取强制的特定 token 约束。
