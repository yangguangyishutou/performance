\textbf{Benchmark.} Our benchmark consists of two programming language datasets: Python and Java. Each dataset contains both member and non-member samples to evaluate membership inference capabilities across different programming paradigms.

\textbf{Members.} For Python, we refer to the Pile dataset which was used as the pre-training corpora for a number of models. Specifically, we extract Python functions from the code portion of the Pile dataset using scripts to generate a JSONL file. From this file, we systematically sample 30 functions from every 100 consecutive entries starting from the beginning, collecting a total of 3,000 entries to obtain 300 functions, resulting in the positive.jsonl file. For Java, the member sample collection is \todo{to be completed}.

% Pile --> Project list XXX         ---->            match 12 project       ---> 10 project --> XXX files ---> 300 functions
%           GitHub projects 20 rank by start     ---filter cookbook -> 12 project   

\textbf{Non-members.} For both Python and Java, we search GitHub repositories using the query "language:python created:>=2024-01-01 pushed:>=2024-01-01" and "language:java created:>=2024-01-01 pushed:>=2024-01-01" respectively to ensure that these codes have not been seen during model training. We extract functions from the repository files using scripts, collecting up to 30 functions from each repository before proceeding to the next one. This process generates the negative\_raw.jsonl file (containing more than 300 entries) for each language. We select the first 300 entries as our negative sample set for both Python and Java.


\textbf{Length.} We define the length of a code snippet as the number of characters in the function field. We divide the character length into three categories based on statistical distribution: short (character length < 33rd percentile), medium (33rd percentile $ \le $ character length < 66th percentile), and long (character length $\ge$ 66th percentile).
