\section{Benchmark Construction}

Existing MIA benchmarks, \eg WikiMIA~\cite{shi2023detecting} and MIMIR~\cite{duan2024membership}, are designed to evaluate MIAs on generic data elements. They can not accurately capture MIA capabilities on code or the extent to which LLMs utilize copyrighted code.
\todo{Although the benchmark from Yang et al.~\cite{yang2024gotcha} targeted code, it has several limitations for our study. Their benchmark only covers the Java language and relies on the general-purpose CodeXGLUE~\cite{lu2021codexglue}. Furthermore, their MIA method requires training an auxiliary classifier, which constitutes a complete attack pipeline. Our study, however, requires a purer benchmark consisting only of member and non-member samples to directly evaluate our method's performance on the LLM, rather than assessing a complex attack process involving auxiliary models. Our time-based construction of the benchmark is therefore more direct and better aligned with the goal of evaluating the model's "memory".}
Therefore, we constructed a new benchmark, named \benchmark, using code from two widely used programming languages, namely Python and Java. Specifically, we collected member and non-member samples as follows.

\textbf{Members.} We leveraged The Pile~\cite{pile}, a large-scale open-source language modeling dataset composed of multiple smaller datasets, including 7.6\% of a repository dataset sourced from GitHub~\cite{thepile}. The Pile released in 2021, serving as the training dataset for many LLMs, including \todo{Pythia~\cite{biderman2023pythia}, GPT-Neo~\cite{black2021gptneo}, StableLM~\cite{stabilityai2023stablelm}, etc.}

For Python, we extract Python functions (methods) from the code portion of the Pile dataset using scripts to generate a JSONL file. 

From this file, we systematically sample 30 functions from every 100 consecutive entries starting from the beginning, collecting a total of 3,000 entries to obtain 300 functions, resulting in the positive.jsonl file. 


For Java, we similarly refer to the code portion of the Pile dataset and use scripts to extract 300 Java classes, generating a JSONL file. 

We then employ additional scripts to extract functions from these classes, which serve as our positive samples for the Java dataset.
