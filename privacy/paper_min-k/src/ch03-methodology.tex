Source code is considered a ``literary work'' under copyright law. The ``literary work'' can be viewed as a sequence of tokens arranged to reflect the author's intentions. Existing MIA techniques\todo{CITE} treat all source code tokens equally and compute membership probabilities of a LLM based on a sample of these tokens. Generally, it is recognized that elements such as variable names, data and control flows, and API usage together with the involved variables, embody the author's intent and serve as indicators of source code authorship. However, we observe that some tokens primarily serve a grammatical purpose, functioning to complete the syntax constraint of the programming language.

The inherent structural duality of source code—simultaneously embodying \textit{human design intent} and \textit{machine-enforced syntax}—introduces unique challenges for membership inference in code language models. A large-scale crawl of open-source Python repositories shows that over half of all tokens belong to such grammar patterns (e.g., \texttt{for-in}, \texttt{try-except}). These ubiquitous structures raise two practical obstacles: Syntax-Induced Noise Amplification(language-mandated tokens exhibit near-identical distributions across samples, drowning discriminative signals) and Contextual Ambiguity (inability to distinguish syntax-enforced vs. meaningful occurrences). The root challenge stems from code's \textit{mandatory scaffolding} property: any correct implementation embeds intent within rigid grammatical constraints, creating persistent noise for MIA.


\subsection{Syntax Constraints}
To address these issues, we construct an \emph{identifier-aware syntax mask} to filter out grammar noise while preserving semantic integrity. The process begins by parsing the code snippet using Python 3.11's \texttt{ast} module to extract all variable, function, and class names, mapping them to their exact character spans in the source via \texttt{lineno} and \texttt{col\_offset}. These spans form a whitelist $\mathcal{W}$ that protects identifiers from removal. Next, we tokenize the code with \texttt{return\_offsets\_mapping=True} to align each subword token with its source offsets. We then initialize a boolean mask $\mathbf{m}$ to true (keep) and set entries to false for tokens matching grammar categories: formatting placeholders (e.g., \texttt{[PAD]}, indents), closing keywords (\texttt{else}, \texttt{except}, etc.), structural symbols (brackets, colons, etc.), punctuation/operators, and attribute dots. If a token's span overlaps $\mathcal{W}$, we revert $\mathbf{m}$ to true.

Our approach exploits code's dual predictability—grammar tokens are highly deterministic while author choices reveal memorization. By filtering the former, we enhance MIA signals without losing semantic content.


\subsection{Min-k\% Prob with Syntax-Aware Filtering}
We propose \textbf{Syntax-Aware Min-k\% Prob}, an enhanced membership inference metric tailored for code.  After applying the identifier–aware mask, we retain only the log-probabilities $\ell_i=-\log p(t_i\,|\,t_{<i})$ at positions where $\mathbf{m}[i]=1$ and renormalise them to $\tilde{\ell}_i$.  Tokens are ordered by $\tilde{\ell}_i$ and the average of the hardest $k\%$ constitutes the score:
\[
\text{SAMin-}k\%(x)=\frac{1}{|\mathcal{S}|}\sum_{i\in\mathcal{S}}\tilde{\ell}_i, \qquad \mathcal{S}=\text{top-}k\%\big(\{\tilde{\ell}_i\}\big).
\]
Filtering grammar tokens ensures the score is dominated by author–specific choices rather than predictable scaffolding.  The whitelist constraint further guarantees that an identifier, even when split into multiple sub-tokens, is scored as a whole rather than partially suppressed.

\paragraph{Renormalisation.}  Let $\mathcal{K}=\{i\mid \mathbf{m}[i]=1\}$ denote the indices kept by the mask.  For each $i\in\mathcal{K}$ we compute a length-normalised log-probability
\[
\tilde{\ell}_i\;=\;\frac{\ell_i}{|\mathcal{K}|}, \qquad \ell_i=-\log p(t_i|t_{<i}).
\]
This normalisation removes bias from variable sequence lengths once grammar tokens have been excised.

Syntax-aware masking converts a token-level metric into a semantics-level one: only tokens that could plausibly encode authorship survive, yet no identifier is ever broken.  This design preserves fidelity to the original Min-$k\%$ principle while eliminating its chief source of noise in code.
