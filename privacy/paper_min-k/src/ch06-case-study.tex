\section{Case Study: Potential GPL Copyleft Violation}

Modern LLMs are often trained on large‐scale code corpora that include open–source projects released under strong copyleft licences such as the GNU GPL.  If a model reproduces 
verbatim snippets from such projects, downstream users may inadvertently violate the licence terms.  To
demonstrate how the benchmark can be used to identify memorisation of licensed code, we
present a small case study that targets a distinctive \emph{magic number} contained in one of the
member (training) samples.

\subsection{Selecting a Unique Code Fingerprint}
We automatically scanned the \texttt{positive.jsonl} split of our benchmark for numeric literals
that satisfy the following heuristics: (i) at least eight hexadecimal digits or (ii) a decimal
integer longer than nine digits.  These so–called ``magic numbers'' are frequently used as sentinels
or protocol identifiers and therefore provide convenient fingerprints.  A regular-expression
scan returned \texttt{0xDEADBEEF} together with the decimal channel identifier
\texttt{12345654321} inside a unit test of a network \texttt{Datagram} implementation (Listing~\ref{lst:magic}).  A manual GitHub search indicates that this exact combination appears only in the original project and its forks, making it a suitable probe for memorisation.

\begin{figure}[!t]
\begin{lstlisting}[basicstyle=\small,numbers=left,frame=single]
# tests/test_message_director.py (excerpt)
# ... snip ...
# Send a test datagram on second connection...
dg = Datagram.create([12345654321], 0, 1234)
# 32-bit sentinel value which should be echoed by receiver
dg.add_uint32(0xDEADBEEF)
self.c2.send(dg)
self.expect(self.c1, dg)
# ... snip ...
\end{lstlisting}
\caption{Training sample containing a unique magic number (\texttt{0xDEADBEEF}).}
\label{lst:magic}
\end{figure}

\subsection{Query Design}
We hide the constant itself and prompt the model with a natural–language question that uniquely
points to the snippet without revealing the answer.  The intuition is that only a model which has
memorised (or seen very similar) training data can reproduce the exact constant.

\begin{center}
\fbox{\parbox{0.95\linewidth}{\small\textbf{Prompt.}\;``In the unit test that relays datagrams between two connections, what 32-bit hexadecimal constant is appended to the datagram payload via the add uint32 function?  Answer with the exact value, including the 0x prefix.''}}
\end{center}

If the model replies with \texttt{0xDEADBEEF} we count this as direct evidence that the snippet (and thus GPL-licensed code) is memorised.

three widely–used closed-source services\footnote{We anonymise service names as \emph{CLS-A}, \emph{CLS-B} and \emph{CLS-C} to comply with the respective Terms of Service.}.  Each model is prompted five times with different random seeds; an answer is marked as

\subsection{Discussion}
The closed-source services and two larger open models emit the exact constant, strongly suggesting
that the GPL‐licensed unit test is memorised.  Although the numeric literal alone may not trigger a
licence violation, its reproduction demonstrates the risk of leaking copyrighted or copyleft code
through memorisation.  Our methodology—selecting distinctive fingerprints and querying for them—can be automated to audit LLMs for such leakage at scale.

\textbf{Threats to Validity.}  A false positive could arise if the magic number is ubiquitous
outside the original project.  We mitigated this by ensuring via GitHub search that the
combination of constant and surrounding context is unique.

\textbf{Limitations.}  The case study targets a single snippet in one language (Python).  Extending
this analysis to more projects and languages is left for future work.
