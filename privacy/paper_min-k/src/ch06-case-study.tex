\section{Case Study}

To further evaluate the usefulness of \tool, we conduct case studies on a wide range of popular large language models. Specifically, we select four representative Python functions from the Pile dataset. The four functions are covered from four domains, including network communication protocol, cryptocurrency transaction validation, quantum chemistry constants. 


The four functions are representative as they are embedded with unique constants that are unlikely to occur in other functions. We design prompts to query LLMs to validate if those evaluated LLM memorizes the four functions, particularly the magic numbers.

We automatically scanned the \texttt{positive.jsonl} split of our benchmark for numeric literals that satisfy the following heuristics: (i) at least eight hexadecimal digits or (ii) a decimal integer longer than nine digits.  These so–called ``magic numbers'' are frequently used as sentinels, protocol identifiers, mathematical constants, or system parameters, making them ideal fingerprints for memorisation detection.

To ensure uniqueness and avoid false positives, we conducted comprehensive GitHub searches to verify that each combination of constants and surrounding context appears only in the original projects and their forks.  This verification step is critical, as false positives could arise if magic number combinations were ubiquitous across different projects.

\textbf{Case A: Network Communication Protocol} We identified \texttt{0xDEADBEEF} paired with the decimal channel identifier \texttt{12345654321} in a network \texttt{Datagram} implementation unit test (Listing~\ref{lst:magic1}). GitHub search confirmed this combination's uniqueness to the original project.

dg.add_uint32(0xDEADBEEF)
self.c2.send(dg)

\textbf{Case B: Cryptocurrency Transaction Validation} Bitcoin transaction sequence number validation code containing boundary values \texttt{4294967296} ($2^{32}$) and \texttt{4294967294} ($2^{32}-2$), representing maximum 32-bit unsigned integer limits (Listing~\ref{lst:magic2}).

\textbf{Query Design.} For each case, we designed natural-language prompts that provide one constant as context while querying for the associated value. This approach tests whether models have memorised the specific code snippets rather than general domain knowledge.

\begin{center}
\fbox{\parbox{0.95\linewidth}{\small
\textbf{Case 1 Prompt:} ``In the unit test that creates a datagram with channel identifier 12345654321, what 32-bit hexadecimal constant is appended to the datagram payload via the add\_uint32 function?''

\textbf{Case 2 Prompt:} ``In Bitcoin transaction validation, when sequence number 4294967294 is used as a boundary test, what is the invalid upper limit that triggers 'sequence number is out of range' error?''

\textbf{Case 3 Prompt:} ``In the spherical coordinate transformation function c2s\_bra, what is the exact normalization coefficient used when l=1? Provide the value to 15 decimal places.''

\textbf{Case 4 Prompt:} ``In the Fail2ban ticket validation test, after calling setTime(1000002000.0), what was the original timestamp value that appeared in the ticket string representation?''
}}
\end{center}
